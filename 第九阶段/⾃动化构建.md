> 前置概念：
>
> **npm‑script**：npm 内置任务执行器，在`package.json`的`scripts`字段写 shell/命令行指令，直接调用各类 cli 工具（webpack、sass、eslint等）执行任务。
>
> **Gulp**：独立的**基于Node Stream（文件流）**的任务运行工具，编写`gulpfile.js`，通过代码、插件管道处理文件，做资源编译、压缩、拷贝、监听等自动化工作流。

## 一、核心原理差异
### npm‑script
底层直接调用系统 shell（Windows cmd/powershell、Linux/macOS bash），执行字符串命令；
- 本质就是**命令的封装**，调用各个工具自身的CLI；
- 多任务串行用 `&&`，并行用 `&`；提供`pre/post`钩子；
- JSON格式，**不能写JS逻辑、变量、条件判断**。

示例：
```json
{
  "scripts": {
    "dev": "sass src/scss:dist/css && webpack serve",
    "build": "eslint . && sass src/scss:dist/css && webpack --mode production"
  }
}
```

### Gulp
基于**Node.js Stream流**，内存中流转虚拟文件对象（Vinyl），`.pipe()`管道链式处理文件，**尽量减少磁盘读写**，处理完再一次性落盘。
- 写 JS/TS 文件 `gulpfile.js`，完整JS语法，可以写条件、循环、变量；
- 内置`series()`串行、`parallel()`并行，`watch()`文件监听；
- 通过插件对文件流做转换：编译sass、压缩js、图片压缩、html处理。

示例：
```js
import {src,dest,series,parallel,watch} from 'gulp'
import sass from 'gulp-sass'
import uglify from 'gulp‑uglify'

//编译css
function css(){
  return src('src/scss/**/*.scss')
    .pipe(sass())
    .pipe(dest('dist/css'))
}
//压缩js
function js(){
  return src('src/js/**/*.js')
    .pipe(uglify())
    .pipe(dest('dist/js'))
}
exports.default = series(css, js)
```

## 二、关键维度对比表
|对比维度|npm‑script|Gulp|
|---|---|---|
|**是否需要额外安装**|✅内置，无需额外依赖|❌需要安装gulp + 各类插件依赖|
|**编写载体**|`package.json` scripts字段（JSON，不能写JS逻辑）|`gulpfile.js`，完整JavaScript/TS，支持变量、判断、循环|
|**任务调度**|shell `&&`串行 / `&`并行；仅有简单pre/post钩子，复杂任务编排很笨拙|原生`series()`串行、`parallel()`并行；细粒度任务编排，任务可复用拆分|
|**文件处理机制**|调用第三方CLI，多次读写磁盘；不直接操作文件|**内存Stream流**，文件在内存管道多次加工，最后一次性写入磁盘，IO开销更小，资源处理更快|
|**文件监听**|需要额外安装第三方工具（如`onchange`）|内置强大`watch()`API，原生监听文件变化执行任务|
|**跨平台**|shell语法Windows/macOS/Linux行为不一致，需要cross‑env等库兼容|API统一，跨平台友好|
|**插件生态**|直接使用所有npm包的CLI，不需要专门包装插件|依赖gulp专属流插件；普通npm包不能直接用，需要适配stream|
|**调试能力**|只能看命令行输出，无法断点调试|JS文件，可以断点调试任务逻辑|
|**抽象程度**|薄抽象，直接调用工具原生CLI，问题溯源简单|增加一层流抽象，遇到插件异常排错成本高|
|**适用场景**|任务简单；以模块打包工具（webpack/vite）为主项目；少量脚本、lint、build、serve；现代前端项目主流选择|静态资源多：多css、图片、html、模板处理；复杂多步骤资源流水线；老静态网站、多页面项目；需要细粒度文件转换拷贝场景|

## 三、优缺点总结
### npm‑script
✅优点
1. **零额外依赖**，项目本来就有npm，开箱即用；
2. 薄封装，直接调用工具原生CLI，没有额外插件层；
3. 配置简单清晰，适合现代前端（vite/webpack为主）；

❌缺点
1. JSON不支持JS逻辑，复杂流程写起来冗长；
2. shell语法跨平台坑多；
3. 没有原生文件监听；复杂多任务编排很麻烦；
4. 文件处理靠第三方CLI，磁盘IO频繁。

### Gulp
✅优点
1. 完整JS编程能力，任务拆分复用，复杂流程编排能力强；
2. Stream流机制，内存处理文件，IO少，批量处理静态资源性能好；
3. 原生watch监听；`series/parallel`灵活控制任务顺序；
4. 跨平台API统一。

❌缺点
1. 需要学习gulpAPI、stream概念；插件有学习成本；
2. 依赖gulp系列插件生态，部分插件老旧停止维护；
3. 增加一层抽象，出问题排查链路变长；
4. 现代SPA项目大多交给vite/webpack打包，gulp价值被弱化。
