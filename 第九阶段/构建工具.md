# 前端自动化构建与模块化打包工具
## 一、自动化构建
### 概念
自动化构建：使用工具自动完成**代码压缩、转译、文件复制、监听文件变化、刷新浏览器**等重复工作，提升前端开发效率。

### 1. npm script
`package.json` 中的 `scripts` 配置项，是Node自带的简易脚本工具。
- 无需额外安装第三方库，开箱即用；
- 本质：命令别名，封装终端命令；
```json
"scripts": {
  "dev": "vite",
  "build": "vite build"
}
```
执行方式：`npm run dev`
- 局限：只适合简单任务，复杂多任务流程管理较弱。

### 2. Gulp
基于**流(Stream)**的自动化构建工具，主打**任务流程管理**。
- 擅长：压缩css/js、图片压缩、文件拷贝、监听文件变动；
- 特点：任务化、流程清晰；
- 定位：**任务自动化工具，不是模块打包器**。

### 3. npm script 与 Gulp 的区别
1. **npm script**
轻量、零依赖；适合简单命令；复杂串行/并行任务编写繁琐。
2. **Gulp**
专门的任务构建工具，拥有丰富插件；适合大量重复性静态资源处理；需要学习Gulp API。

> 使用建议：简单项目直接 npm script；大量静态资源处理场景选用Gulp。

## 二、模块化打包工具
作用：前端浏览器不直接支持ESModule/CommonJS混合模块，打包工具把分散的多个模块、js、css、图片**合并、编译、打包成浏览器可直接运行的文件**。

### 1. Webpack
- 最经典、生态最庞大的打包工具；
- 理念：**一切皆模块**（js、css、图片、字体全部视为模块）；
- 通过 loader 处理各类文件，plugin 实现扩展；
- 适用：大型SPA单页应用（Vue2、老React项目大量使用）。

### 2. Rollup
- 面向**类库、组件库**打包（Vue源码就是Rollup打包）；
- 基于ES Module，打包产物干净，无多余引导代码；
- 短板：对静态资源、css处理能力弱，不适合业务项目。

### 3. Parcel
- **零配置打包工具**；
- 自动识别文件、内置各类转换规则，不需要复杂配置文件；
- 适合小型Demo、简单项目；大型项目可控性不足。

### 4. Snowpack
- 基于浏览器原生ES Module，开发阶段**不打包**；
- 按需转换文件，启动速度快；
- 现状：逐步被Vite替代，新项目很少使用。

## 打包工具核心区别总结
|工具|定位|特点|适用场景|
|----|----|----|--------|
|Webpack|应用打包器|生态最强，配置复杂；全能|大型业务前端项目|
|Rollup|类库打包器|输出简洁，基于ESM|封装组件库、JS工具库|
|Parcel|零配置打包|无需配置，上手简单|小型Demo、简单项目|
|Snowpack|原生ESM开发服务器|开发时不打包|已逐步淘汰，被Vite取代|

## 三、难点标注（理解难点）
1. **自动化构建 ≠ 模块化打包**
Gulp/npm script 是**任务自动化**；Webpack/Rollup 是**模块打包**，两类工具用途不一样，不要混淆。
2. Webpack loader 和 plugin 区分
loader：处理文件转换；plugin：构建生命周期钩子，扩展功能。
3. Rollup适合库、Webpack适合业务项目的底层原因
Rollup只处理ES模块，不擅长静态资源；Webpack支持各种模块规范与资源。
4. Vite 和上述工具关系补充（拓展）
Vite开发阶段基于原生ESM（类似Snowpack），生产打包底层调用Rollup。

## 四、实践要点
1. 业务项目：Vue/React项目现在优先 Vite；传统老项目大多 Webpack。
2. 开发组件库、工具函数库：优先 Rollup。
3. 静态资源批量压缩、部署文件拷贝：可以使用 Gulp 或者 npm脚本。
