# JavaScript document.write() 深度理解笔记
## 一、本质定义（底层原理）
>document.write() 是浏览器原生、非常古老的 DOM API，作用是：向浏览器的「HTML 文档解析流」写入字符串内容（支持写入普通文本、HTML标签、JS代码）。
核心本质：它是流式写入，不是 DOM 节点操作。
现代 DOM 操作（innerHTML / createElement）是操作渲染好的 DOM 树；
document.write 是操作浏览器正在解析的 HTML 流。
## 二、两种运行状态（必考核心）
### 1. 页面「解析中」调用（脚本在页面加载期间执行）
脚本写在 HTML 结构内部、页面还没加载完毕：
- 不会清空页面
- 按照代码顺序，原地追加内容
- 属于正常流式输出
```
<body>
  <p>我是原有内容</p>
  <script>
    document.write('新增文字 <b>加粗内容</b>')
  </script>
</body>
```
结果：原有内容保留，脚本位置追加新内容。
### 2. 页面「加载完成后」调用（点击事件、定时器、延迟执行）
这是最大的坑！！！
页面解析完毕、文档流已经关闭，此时再执行 document.write()：
1. 浏览器自动执行 document.open() 重新打开文档流
2. 清空当前页面所有 DOM、所有内容、所有样式、所有事件
3. 只渲染本次 write 写入的新内容
通俗理解：晚调用 = 整页覆盖、页面白屏重写
```
setTimeout(()=>{
  document.write('延迟执行，页面全部被我覆盖')
},1000)
```
## 三、五大核心特性
### 1. 支持解析 HTML 标签
写入的字符串会被浏览器解析为 HTML，不是纯文本（区别于 innerText）。
document.write('<h1>我是标题</h1>')
### 2. 阻塞页面渲染（性能极差）
document.write 是同步阻塞 API。
执行时会暂停 HTML 解析、暂停页面渲染，直到写入完成，严重影响首屏加载性能。
### 3. 无法精细局部修改
只能「流式追加」或「整页重写」，不能精准修改某个盒子内部内容，完全不符合现代组件化开发思想。
### 4. 存在安全风险 XSS
如果写入用户输入内容，会直接解析执行 HTML/JS，造成跨站脚本攻击。
### 5. 现代浏览器降级、限制越来越多
- 异步脚本、延迟脚本中写入会被浏览器忽略或报错
- Chrome 等高版本浏览器对其做性能降级
- XHTML 模式下直接失效
## 四、为什么项目中严禁使用 document.write？（面试标准答案）
1. 破坏 DOM 结构：延迟执行会清空整页，造成页面白屏、事件丢失
2. 阻塞渲染：同步阻塞 HTML 解析，降低首屏速度
3. 无法局部更新：不适合精细化页面开发
4. 存在 XSS 安全漏洞
5. 不符合结构与行为分离原则（HTML结构、JS行为混杂）
6. 现代浏览器对其兼容限制越来越多
## 五、正确替代方案
所有场景，一律用以下 API 替代 document.write
1. 写入纯文本 →innerText
2. 写入 HTML 结构 → innerHTML
3. 标准规范写法 → createElement + appendChild
>优势：局部更新、不毁页面、不阻塞渲染、性能好、安全、可控
## 六、易混点辨析
### 1. document.write 和 innerHTML 区别
- document.write：操作文档流，晚调用清空整页，全局级写入
- innerHTML：操作具体 DOM 节点，只修改当前盒子，安全可控
### 2. 为什么初学经常用？
因为最简单、不用获取 DOM 元素，直接输出内容；但属于老旧、淘汰式写法，仅适合教学演示，禁止用于项目开发。
## 七、一句话终极总结
document.write() 是浏览器早期流式输出 API，用于向 HTML 解析流写入内容。页面加载中可追加内容，页面加载完成后调用会自动打开新文档流、清空整页内容；存在阻塞渲染、破坏DOM、安全隐患等问题，现代开发完全废弃，统一使用 innerHTML 或创建节点方式替代。
