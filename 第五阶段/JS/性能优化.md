# 前端性能优化

> E36考点：面试高频，会概念、会手写简易代码、会区分使用场景、知道优缺点

## 一、前端性能优化总览

性能优化目标：**页面加载更快、交互更流畅、减少内存占用、减少无效重复执行**

### 1.加载层面优化（网络请求）

1. **资源压缩**

- JS/CSS压缩去掉空格换行；图片压缩（webp格式）

2. **减少HTTP请求**

- 合并css、js；雪碧图；减少图片数量

3. **缓存策略**

- 强缓存、协商缓存，静态资源缓存，重复访问不用重新下载

4. 懒加载

- 图片懒加载：图片进入视口才加载图片，减少首屏请求

```
<img loading="lazy" src="xxx">
```

5. CDN：静态资源放到CDN，就近访问加速

### 2.DOM层面优化

> 
> DOM操作非常消耗性能，DOM操作会触发浏览器重排重绘

- **重排(reflow)**：元素几何尺寸、位置发生改变，浏览器重新计算所有盒子布局，**开销大**> 
> 触发：宽高、margin、offset、dom增删
- **重绘(repaint)**：只是颜色、背景改变，不改变位置大小，开销比重排小> 
> 触发：color、background

✅DOM优化手段

1. 尽量减少DOM操作，不要频繁操作dom
2. 不要循环内频繁获取dom offset/scrollTop（会触发重排），提取到循环外面
3. 使用文档碎片`createDocumentFragment`批量插入DOM，减少页面渲染次数
4. 尽量使用CSS属性`transform、opacity`做动画，这两个属性直接进入合成层，**不会触发重排重绘**

### 3.JS层面优化

1. 避免阻塞主线程；耗时操作放到定时器、异步
2. **防抖、节流**：解决高频事件重复执行问题（重点下面细讲）
3. 及时清除定时器、事件监听，防止内存泄漏
4. 闭包不要滥用，避免变量无法释放造成内存泄漏

### 4.工程化优化

1. webpack/vite打包压缩，代码分割，按需导入
2. tree‑shaking，删除没有使用的代码

# 二、防抖 debounce

## 概念

> 
> **触发事件之后，延迟n毫秒再执行函数；如果n毫秒之内再次触发事件，就重新计时。**
> 通俗理解：**等用户停下来之后，再执行一次。**
> 例子：坐电梯，有人进来就重新等10秒，没人进来，才关门运行。

### 使用场景（考试必背）

1. 搜索框输入联想：输入文字不立刻发请求，等用户停止输入再发接口请求，避免每敲一个字就请求后端
2. window窗口resize窗口大小改变
3. input输入框监听
4. 表单输入校验

### 手写简易防抖代码

```
/**
 * @param fn 需要防抖的函数
 * @param delay 延迟毫秒
 * @returns 防抖处理后的函数
 */
function debounce(fn, delay) {
  let timer = null;
  return function (...args) {
    // 如果定时器存在，清除旧定时器
    if(timer) clearTimeout(timer);
    //重新开启定时器
    timer = setTimeout(()=>{
      fn.apply(this, args)
      timer = null
    }, delay)
  }
}

//使用示例
const searchHandler = debounce(function(e){
  console.log('发送搜索请求',e.target.value)
},500)

//绑定输入事件
input.addEventListener('input',searchHandler)
```

> 
> 逻辑：疯狂输入，不断清除旧定时器，只有停止输入500ms之后，函数才执行1次

### 缺点

多次触发，只有最后一次执行；中间的触发全部丢弃。

# 三、节流 throttle

## 概念

> 
> **固定时间间隔内，函数最多只执行1次。**
> 通俗理解：**不管事件触发多频繁，每隔固定时间，保证执行一次。**
> 例子：游戏技能冷却，1秒只能释放一次技能，狂点也不会多次释放。

### 使用场景（必背）

1. scroll滚动事件（页面滚动获取滚动位置）
2. mousemove鼠标移动
3. 按钮高频点击防止短时间多次提交
4. 拖拽mousemove

### 简易时间戳版节流

```
function throttle(fn, interval) {
  let lastTime = 0
  return function(...args){
    const now = Date.now()
    if(now - lastTime >= interval){
      fn.apply(this, args)
      lastTime = now
    }
  }
}

//使用：滚动事件，每500ms最多执行一次
window.addEventListener('scroll',throttle(function(){
  console.log('滚动',window.scrollY)
},500))
```

### 定时器版本节流

```
function throttle(fn,delay){
  let timer = null
  return function(...args){
    if(!timer){
      timer = setTimeout(()=>{
        fn.apply(this,args)
        timer = null
      },delay)
    }
  }
}
```

> 
> 时间戳版本：立刻执行第一次；定时器版本：延迟才执行第一次

## ✅防抖 vs 节流对比表格（复习背诵）

|  | 防抖 debounce | 节流 throttle |
| --- | --- | --- |
| 核心逻辑 | 多次触发，**等待停止后执行一次** | 高频触发，**每隔一段时间执行一次** |
| 比喻 | 电梯，来人就重新倒计时 | 技能冷却，固定间隔允许执行一次 |
| 典型场景 | 搜索框输入、resize窗口大小 | scroll滚动、鼠标移动mousemove、拖拽 |
| 执行次数 | 停止触发之后执行1次 | 过程中均匀的间隔执行多次 |

> 
> 📌一句话记忆：
> **防抖：等停下来再干活；节流：干活不能太急，隔一段时间干一次。**


### 1.为什么要用防抖节流？

> 
> 像`input、scroll、mousemove`这类事件短时间会疯狂触发几十上百次，每一次触发都会执行处理函数，大量执行JS，造成页面卡顿，占用CPU。
> 防抖节流用来**降低函数执行频率，减少无效重复调用，优化页面交互性能。**

### 2.防抖节流区别

- 防抖：连续触发只执行最后一次，适合输入类场景；
- 节流：限制单位时间最多执行一次，保证过程中间有执行，适合滚动鼠标移动。

### 3.重排重绘怎么优化？

1. 使用transform、opacity做动画，进入合成层，跳过重排重绘
2. 批量DOM操作，不要频繁读写DOM样式
3. 读写DOM操作分开，不要读写交替，减少浏览器强制同步布局

### 4.图片懒加载原理

监听图片是否进入视口，进入可视区域才把`data‑src`赋值给`src`，实现延迟加载，减少首屏资源请求。

## 易错坑点

1. 防抖节流返回的是**新函数**，事件监听要接收返回值，不要直接把原始函数丢进去
2. 组件销毁的时候，需要清除定时器，防止内存泄漏
3. 防抖适合输入框，不要拿防抖做滚动；滚动用节流，不然滚动结束才执行，中间拿不到滚动位置。
