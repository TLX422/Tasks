## 简单概念

> 
> **同步：代码从上到下，立刻执行，做完一行才走下一行，阻塞主线程。**
> **异步：注册任务，不会立刻执行；先跳过，等未来某个条件满足，再放入事件队列，等同步代码全部跑完之后才执行。**
> ⚠️重点区分两件事：**「注册事件」是同步；「事件回调函数执行」是异步。**

---

## 逐行区分同步 / 异步

### ✅全部同步代码（页面加载，script从上往下执行阶段）

```
// 同步1：DOM查询，立刻执行
var nh=document.getElementById('nh')

// 同步2：给onclick属性赋值，只是把函数存到元素对象上，**函数体没有运行**
nh.onclick=function(){
    console.log("点击了");
}

// 同步3：addEventListener，只是把回调函数注册到事件监听列表，**回调不会立刻执行**
nh.addEventListener("click",function(){
    console.log('点击了23244'); 
})
```

> 
> 上面这三行，页面加载脚本执行的时候**马上跑完**。
> 这里的两个 function 只是**函数定义/函数对象**，里面的 `console.log` 此时完全没有执行！
> `addEventListener`、`xxx.onclick = fn` 本身这个**注册动作是同步**。

### ⚡异步行为（未来用户点击按钮的时候才触发）

当**用户鼠标点击按钮**：浏览器把两个回调函数加入任务队列。
等到当前同步栈清空，再依次执行：

```
// 异步回调1，点击时才执行
function(){
    console.log("点击了");
}
// 异步回调2，点击时才执行
function(){
    console.log('点击了23244'); 
}
```

输出顺序：

```
点击了
点击了23244
```

> 
> 👉**事件回调函数的执行，属于浏览器的异步事件循环。**


> 坑点：很多同学误以为 `addEventListener` 是异步，错！
> `addEventListener` **API调用本身同步**；被传入的回调函数，执行时机是异步。

# 例子

```
// 同步：定义函数，此时不执行
function fn(){
  console.log('hello')
}
// 同步：只是把fn存起来，不是调用
btn.onclick = fn;  

// 如果加括号！同步立刻执行！
btn.onclick = fn(); 
// 等价于先执行fn()拿到返回值，再赋值给onclick，页面加载就打印hello，点击无效。
```

## 总结一句话

> 
> **事件注册是同步；事件回调的执行是异步。**

### 拓展：事件循环视角看整个流程

1. 解析HTML，遇到`<script>`，进入JS执行上下文（同步栈）
2. 同步执行 `getElementById` → 拿到按钮
3. 同步执行 `nh.onclick = function(){...}`：保存函数引用
4. 同步执行 `addEventListener`：把回调存入元素事件列表
5. **script全部执行完毕，同步调用栈清空**
6. 等待：浏览器空闲，监听用户输入（这一步是浏览器后台，JS线程不阻塞）
7. 用户点击按钮 → 浏览器将两个回调放入**宏任务队列**
8. 同步栈是空，取出宏任务，依次运行两个回调，打印两条log。

> 
> 鼠标点击、click事件属于**宏任务**。
