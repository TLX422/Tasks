# 包管理学习笔记
---
## 一、什么是包管理
### 1. 包的定义
包就是开发者封装好的、可复用的代码模块，比如UI组件库、工具函数库、框架源码（如Vue、Element Plus）。

### 2. 包管理的含义
包管理是一套标准化机制，借助工具实现**第三方依赖的安装、卸载、升级、版本锁定、环境统一**。
### 3. 解决的核心痛点
1. 无需手动下载、拷贝JS库文件，一行命令完成安装；
2. 自动处理依赖嵌套、版本冲突问题；
3. 通过配置文件记录依赖清单，团队协作一键还原项目环境；
4. 区分开发环境依赖与生产上线依赖，精简打包体积。

## 二、主流包管理工具：npm / yarn / pnpm
### 1. npm
>[npm使用](https://www.runoob.com/nodejs/nodejs-npm.html)
- 全称 Node Package Manager，**Node.js 自带**，安装Node环境后直接可用，无需额外安装；
- 官方标准包管理器，生态最完善，兼容性最强；
- 版本锁定文件：`package-lock.json`。

### 2. yarn
>[yarn使用方法](https://blog.csdn.net/LIZHUOLONG1/article/details/125534086)
- 由Meta（原Facebook）推出，早期为弥补旧版npm安装慢、版本锁定不稳定的缺陷；
- 曾以并行安装、严格版本锁著称；
- 版本锁定文件：`yarn.lock`；
- 现状：新版本npm功能已补齐，新项目基本不再优先使用yarn。

### 3. pnpm
>[pnpm使用方法](https://www.runoob.com/nodejs/nodejs-pnpm.html)
- 新一代高性能包管理器，Vue官方、Vite官方主推工具；
- 底层采用硬链接+内容寻址存储，**安装速度最快、磁盘占用最少**；
- 版本锁定文件：`pnpm-lock.yaml`。

### 三者核心区别汇总
| 工具 | 锁版本文件 | 核心优缺点 | 适用场景 |
|------|------------|------------|----------|
| npm | package-lock.json | Node自带、兼容性拉满；早期性能较差 | 通用老项目、追求稳定兼容 |
| yarn | yarn.lock | 早期解决npm短板，现在优势弱化 | 老旧历史项目维护 |
| pnpm | pnpm-lock.yaml | 速度最快、极致节省硬盘空间 | 所有新项目首选 |

> 重要规范：**一个项目只允许使用一种包管理器**，禁止混用npm/yarn/pnpm，避免锁文件冲突。

## 三、Vue工程标准文件结构
```
vue项目根目录
├── node_modules/          # 自动下载的第三方依赖包（禁止提交到Git/GitHub）
├── public/                # 静态公共资源（图片、ico图标）
├── src/                   # 项目业务源代码
│   ├── components/        # 公共组件
│   ├── views/             # 页面视图
│   ├── router/            # 路由配置
│   ├── store/             # 状态管理（Pinia/Vuex）
│   └── main.js            # 项目入口文件
├── package.json           # 项目核心配置文件（必须提交版本库）
├── pnpm-lock.yaml        # 依赖版本锁定文件（必须提交版本库）
├── vite.config.js         # 构建工具配置
└── .gitignore             # Git忽略文件配置（过滤node_modules等）
```

### 关键注意点
`node_modules`文件夹体积庞大，且可通过`package.json`+锁文件执行安装命令重新生成，必须写入`.gitignore`忽略，不要上传GitHub。

## 四、package.json 配置规范
`package.json`是项目的“配置说明书”，定义项目基础信息、运行脚本、依赖清单。

### 核心字段详解
```json
{
  "name": "vue-study-demo",
  "version": "1.0.0",
  "description": "Vue学习演示项目",
  "scripts": {
    "dev": "vite",
    "build": "vite build",
    "preview": "vite preview"
  },
  "dependencies": {
    "element-plus": "^2.8.4"
  },
  "devDependencies": {
    "vite": "^6.0.0",
    "vue": "^3.5.0"
  }
}
```
1. **基础信息**
`name`：项目名称；`version`：项目语义化版本号。

2. **scripts 自定义脚本**
配置命令别名，终端执行 `npm run dev` 即可启动项目开发服务器。

3. **dependencies 生产依赖**
项目打包上线后依然需要运行的库，直接 `npm install xxx` 默认安装到此。

4. **devDependencies 开发依赖**
仅本地开发、编译构建时使用，上线打包会被剔除；安装指令：`npm install xxx -D`。

### lock锁定文件作用
`package-lock.json` / `pnpm-lock.yaml` 会锁定每一个依赖**精确到小版本**，保证不同电脑、不同环境安装出来的依赖版本完全一致，杜绝版本差异导致的bug。

## 五、环境优化：配置阿里npm镜像源
npm默认官方服务器在海外，国内下载依赖速度极慢，切换为阿里淘宝镜像源大幅提速。

### 1. 查看当前使用的源
```bash
npm config get registry
```

### 2. 设置阿里镜像（推荐）
```bash
npm config set registry https://registry.npmmirror.com
```

### 3. 恢复官方原始源（发布npm包时使用）
```bash
npm config set registry https://registry.npmjs.org
```

### 拓展：pnpm/yarn 配置镜像
```bash
# pnpm设置镜像
pnpm config set registry https://registry.npmmirror.com

# yarn设置镜像
yarn config set registry https://registry.npmmirror.com
```

## 六、核心考点精简总结
1. 包管理本质：统一管理前端项目第三方依赖，规范版本与项目环境；
2. 优先级选型：新项目优先pnpm，老项目沿用原有npm/yarn；
3. 两个必须提交Git的文件：`package.json` + 锁文件；绝对不能提交：`node_modules`；
4. `-D` 参数作用：将依赖安装为开发依赖，不参与项目最终打包；
5. 镜像源目的：解决国内外网访问缓慢问题，提升依赖下载速度。
