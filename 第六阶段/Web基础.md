## 一、基础网络概念
### 1.互联网
互联网是全球无数计算机网络通过通信协议互相连接形成的巨大网络集合。
- 本质：**实现不同设备之间的数据传输与资源共享**。
- 网页访问完整本质：你的电脑（浏览器） → 互联网 → 远端服务器，双向收发数据。
- 网络通信必须遵守协议，前面学习的 TCP、HTTP 就是互联网通信规则。

### 2.⭐ 域名 Domain Name
域名是服务器IP地址的别名，专门解决IP数字难记忆的问题。
> 示例：`www.baidu.com`
1. **域名层级（从右向左读）**
    |部分|说明|
    |----|----|
    |`.com`|顶级域名，代表机构类型(com商业、cn中国、org组织)|
    |`baidu`|二级域名，主体域名，需要注册购买|
    |`www`|子域名，可以自定义，代表服务器服务|
2. 重要区分
    - 域名 ≠ 网站：域名仅仅是名字，必须解析绑定服务器IP，服务器存放网页资源，才能打开网站。
    - 域名需要注册购买；一个域名可以解析到不同IP，一个IP也可以绑定多个域名。

### 3.⭐ DNS 域名系统 Domain Name System
DNS相当于互联网的**电话簿**。
>例子：输入 `www.baidu.com` → DNS 查询 → 解析出百度服务器 IP。
1. **核心功能：域名 ↔ IP地址互相转换**
    浏览器只能通过IP找到服务器硬件，但人记不住数字IP，所以需要DNS翻译。
2. DNS完整查询顺序（浏览器输入域名后）
    1. 查**浏览器DNS缓存**：浏览器之前访问过，短期保存域名-IP映射
    2. 查操作系统本地缓存，读取本机 `hosts` 文件，可以手动配置域名对应IP
    3. 向本地运营商DNS服务器发起查询
    4. 本地DNS没有记录，就向根域名服务器、顶级域名服务器递归查询，最终拿到服务器IP
3. 小知识：DNS劫持，恶意篡改解析结果，把域名解析到错误IP。

### 4.服务器
服务器就是一台长时间开机、接入互联网的高性能计算机。
1. 作用：存储网页资源（HTML/CSS/JS、图片、接口数据、数据库）；接收浏览器HTTP请求，返回资源。
2. 常见分类
    - Web服务器(Nginx/Apache)：处理网页HTTP请求
    - 数据库服务器：存储业务数据
    - 文件服务器：存放图片视频静态资源
3. 客户端（浏览器）发请求，服务器做响应，属于**C/S客户端-服务器模式**。

### 5.浏览器
浏览器是客户端软件（Chrome、Edge、Firefox）。
> 两大核心模块：**网络模块**（收发HTTP请求） + **渲染引擎**（解析代码绘制页面） + **JS引擎**（执行JavaScript代码）。

## 二、浏览器内部核心知识点
### 1. DOM事件流

>[CSDN:DOM是什么](https://blog.csdn.net/wei1273356078/article/details/106543967)
**DOM树形结构**
![](https://www.runoob.com/images/htmltree.gif)
![](https://i-blog.csdnimg.cn/blog_migrate/f4f8204f0bf34035c59762c7f9edf1e7.png#pic_center)



DOM事件流描述：当页面触发事件（点击click）时，事件在DOM树节点之间**传递流动的完整过程**。
一共分为**捕获阶段、目标阶段、冒泡阶段**三个阶段。

1. **捕获阶段（向下）**
事件从最顶层`window` → `document` → html → body，一层层**向子元素往下传递**，直到真正被点击的元素。
> 默认不会触发捕获，需要手动开启。

2. **目标阶段**
事件抵达真正被点击的DOM元素，执行绑定的事件回调函数。

3. **冒泡阶段（向上）**
事件从被点击的目标元素开始，一层一层向上传给父元素，一直冒泡到window对象。
> `addEventListener('click',fn,false)`第三个参数为false，默认监听**冒泡阶段**。

```js
// 开启捕获阶段监听，第三个参数设置为 true
dom.addEventListener('click', ()=>{}, true)
```

- 阻止冒泡：`event.stopPropagation()`，事件不再向上冒泡。
- 阻止默认行为：`event.preventDefault()`，阻止a标签跳转、表单提交等原生行为。

### 2. 事件委托
---
#### 事件委托也称之为事件代理（Event Delegation）。是JavaScript中常用绑定事件的常用技巧。顾名思义，“事件代理”即是把原本需要绑定在子元素的响应事件委托给父元素，让父元素担当事件监听的职务。事件代理的原理是DOM元素的事件冒泡。

>[CSDN:事件委托](https://blog.csdn.net/Wps1919/article/details/124680326)
**底层依赖事件冒泡机制**。
#### 场景
有很多子元素需要绑定点击事件，还包括后续JS动态新增出来的子DOM。
> ❌ 传统写法：循环给每一个子元素绑定事件；新增元素还要重新绑定，消耗内存，容易遗漏。

#### 原理
不给子元素绑定事件，**只给所有子元素共同的父元素绑定一次事件**。
点击子元素后，事件冒泡到父元素；父元素通过`event.target`拿到真正被点击的子元素，再执行业务逻辑。

## 运行流程一步步拆解
```
1. 鼠标点击 `<li>`
2. 产生点击事件
3. **事件冒泡**：事件从 li 向上跑到父元素 ul
4. ul 事先绑定了 click 监听器，触发函数
5. `e` 接收本次事件信息
6. 使用 `e.target` 查出你点的标签
7. 判断标签是否为 `LI`，满足条件执行代码
```
#### 优点
1. 减少事件监听器数量，节省内存，性能更好
2. **自动支持未来动态新增的DOM节点**，新增子节点不需要重复绑定事件

示例伪代码
```js
// ul是父容器，li是子元素
const ul = document.querySelector('ul')
ul.addEventListener('click', function(e){
  // e.target 就是实际点击到的元素
  if(e.target.tagName === 'LI'){
    console.log('点击了li',e.target.innerText)
  }
})
```

### ⭐浏览器加载全过程
## 1. DNS 解析

作用：域名 → IP 地址
我们输入 `www.baidu.com`（域名，方便人记）
计算机通信只认识 IP 数字地址。
流程：
浏览器缓存 → 操作系统缓存 → DNS 服务器查询
最终拿到服务器 IP。

> 
> DNS：Domain Name System 域名系统

## 2. TCP 三次握手（建立连接）

浏览器（客户端） ↔ 服务器
建立可靠连接，保证数据稳定传输。

1. 客户端：请求连接（SYN）
2. 服务器：收到，同意连接（SYN+ACK）
3. 客户端：确认，开始传输数据（ACK）

> 
> TCP：传输控制协议，可靠、面向连接

## 3. 发送 HTTP / HTTPS 请求

浏览器向服务器发送请求报文
服务器收到请求，返回 **响应报文**，把 HTML 文件发回来。

## 4. 接收资源，开始解析渲染（最重要！）

服务器传回 HTML 文件，浏览器开始解析

### 4.1 解析 HTML → 生成 DOM 树

HTML 从上往下一行一行解析
构建 **DOM Tree（文档对象模型树）**
标签一层层形成树形结构。

> 
> ⚠️遇到 `<script>` JS 文件：
> 默认**阻塞解析**！停止解析 HTML，下载并执行 JS。
> 原因：JS 可以修改 DOM。

### 4.2 解析 CSS → 生成 CSSOM 树

CSSOM：CSS 对象模型树，存放所有样式规则。

### 4.3 合成 渲染树 Render Tree

DOM 树 + CSSOM 树 结合
**只包含需要显示的元素**（display:none 的元素不会进入渲染树）

### 4.4 布局 Layout（回流）

计算每个元素：大小、位置、坐标。

> 
> 回流（重排）：元素尺寸 / 位置变化，重新计算布局。开销大！

### 4.5 绘制 Paint（重绘）

按照布局结果，填充颜色、图片、文字、阴影。
只改颜色背景：只会触发重绘，不触发回流。

### 4.6 合成 Composite（可选）

页面分层（transform、opacity 开启图层），多线程绘制，提升性能。

## 5. TCP 四次挥手（断开连接）

数据传输完毕，双方友好关闭连接

1. 浏览器：我不再发数据（FIN）
2. 服务器：收到（ACK）
3. 服务器：我数据发完了（FIN）
4. 浏览器：确认关闭（ACK）

## 6. 后续：页面加载完成

图片、字体等**外部资源**继续异步加载

# 📌精简总流程背诵版

1. DNS 解析：域名翻译 IP
2. TCP 三次握手：建立连接
3. 发送 HTTP 请求，接收 HTML
4. 解析渲染阶段
HTML→DOM 树｜CSS→CSSOM 树 → 渲染树 → Layout 布局 (回流) → Paint 绘制 → Composite 合成
5. TCP 四次挥手：断开连接


### ⭐浏览器渲染过程（拿到HTML、CSS后如何绘制页面)
>[游览器渲染揭秘](https://blog.csdn.net/RenGJ010617/article/details/140212872)
![](https://i-blog.csdnimg.cn/direct/0ab93539c06d40f0ae37e456f7162ea8.png)
六大步骤：构建DOM树 → 构建CSSOM树 → 生成渲染树 → 布局(回流 reflow) → 绘制(重绘 repaint) → 图层合成
![](https://i-blog.csdnimg.cn/direct/7c9d120d531e479b92b6a828e9951487.png)
1. **构建DOM树**
解析HTML文本，生成DOM节点树，包含页面所有标签节点。

2. **构建CSSOM树**
解析所有CSS（行内、style标签、外部css文件），生成CSSOM样式对象树，存储每个节点的样式规则。

3. **生成Render Tree渲染树**
把DOM树 和 CSSOM树结合，**只收集需要显示的节点**。
> `display:none`的节点不会进入渲染树；`visibility:hidden`会进入渲染树只是看不见。

4. **布局 Layout（回流 reflow）**
计算渲染树上每一个元素**几何信息**：元素的宽高、在页面中的位置。
> 只要元素大小、位置发生变化，浏览器就要重新布局，就是回流。**回流开销很大，尽量减少**。

5. **绘制 Paint（重绘 repaint）**
按照布局计算出来的位置，填充像素：绘制颜色、背景、文字、阴影。
> 如果仅仅修改颜色背景，不改变大小位置，只会触发重绘，不会触发回流，开销比回流小。

6. **合成 Composite**
页面分为多个图层，浏览器把各个图层合并，输出最终图像到屏幕。transform、opacity属性可以触发合成，**不会触发回流重绘，性能很高**。

> 总结
> - 回流(reflow)：改变几何布局 → 开销最大
> - 重绘(repaint)：只改外观颜色，不改布局 → 开销中等
> - 合成(composite)：transform / opacity → 开销最小

### 3. 事件循环 Event Loop
> JavaScript 是**单线程**，同一时间只能做一件事。遇到异步任务不会阻塞，交给浏览器，等完成后放入队列，主线程空闲就去取任务执行，这套机制就是**事件循环**。

## 任务分类

1. **同步任务**：立刻执行，在主线程执行栈，从上到下执行。
2. **异步任务**：放到后台，等待条件满足再进入队列。
异步分为 **宏任务 (macro‑task)**、**微任务 (micro‑task)**

### ✅ 宏任务 MacroTask

- `script` 整体代码（整个 JS 文件）
- `setTimeout`、`setInterval`
- ajax 请求、DOM 事件（click 等）

### ✅ 微任务 MicroTask（优先级高于宏任务）

- `Promise.then / catch / finally`
- `async/await`（await 后面代码属于微任务）
- `MutationObserver`

## 📌 执行顺序

1. 执行**同步代码**，遇到异步就丢给浏览器处理
2. **同步执行栈清空之后，先把所有微任务全部执行完**（全部跑完，不是跑一个）
3. 再取**一个宏任务**执行
4. 这个宏任务执行完，**再次清空所有微任务**
5. 再取下一个宏任务…… 循环往复，就是事件循环

> 
> 口诀：**同步优先 → 清全部微任务 → 执行一个宏任务 → 再清全部微任务**

## 简单示例

```
console.log('1')
setTimeout(()=>{
  console.log('2')
})
Promise.resolve().then(()=>{
  console.log('3')
})
console.log('4')
```

输出顺序：`1 → 4 → 3 → 2`

解析：

1. `console.log('1')` 同步
2. setTimeout 宏任务，放入宏队列
3. Promise.then 微任务，放入微队列
4. `console.log('4')` 同步，同步栈清空
5. **清空全部微任务：打印 3**
6. 取 1 个宏任务执行：打印 2

## async /await 简单理解

`await` 前面是同步；**await 后面的代码，相当于放到 Promise.then，属于微任务**。

```
async function fn(){
  console.log('A')
  await 100
  console.log('B') //微任务
}
fn()
console.log('C')
```

输出：`A → C → B`

## 浏览器事件循环流程图

```
执行栈（同步代码）
     ↓
执行栈为空 → 执行【所有微任务】
     ↓
取出【一个宏任务】执行
     ↓
回到上面，再次清空微任务
循环往复
```
### 4. Headless Browser 无头浏览器
>[菜鸟教程：无头游览器](https://www.runoob.com/selenium/selenium-headless.html)

无头浏览器模式（Headless Mode）是指在没有图形用户界面（GUI）的情况下运行浏览器，换句话说，浏览器在后台运行，不会弹出可见的窗口。
无头浏览器 = **没有图形GUI界面的浏览器内核**，在后台命令行静默运行。
- 代表工具：Puppeteer(Chrome无头)、Playwright
- 典型用途
  1. 网页自动化爬虫，执行JS渲染动态页面
  2. E2E端到端自动化测试，模拟用户点击访问网页
  3. 网页截图、生成PDF
  4. 简单服务端SSR渲染页面
- 特点：拥有完整浏览器内核，可以执行JS，但是没有窗口界面。

### 5. WebView
> WebView是**浏览器内核组件**，剥离掉浏览器地址栏、按钮这些外壳，只保留解析渲染网页的核心能力。
## 概念

**WebView** 是移动端（Android /iOS）内置的浏览器内核组件，相当于一个**嵌入 APP 里面的迷你浏览器**。
APP 原生界面里开辟一块区域，用来加载网页 (H5 页面)，可以展示 HTML、CSS、执行 JS。

> 
> 普通 Chrome：独立浏览器 App
> Headless：无界面后台浏览器
> WebView：**嵌入到原生 App 内部的浏览器组件**

## 核心作用

1. App 内嵌 H5 页面，一套 H5 代码，安卓苹果都能用，降低开发成本
2. 活动页、帮助文档、协议页面，经常用 WebView 实现
3. 混合开发（Hybrid）：原生代码 + H5 网页混合

> 
> 比如：APP 里面打开的活动弹窗、小程序底层也大量用到 WebView

## JS 和原生通信

H5 里面的 JS 代码 和 Android/iOS 原生代码，互相调用，叫 **JSBridge**

1. **JS 调用原生**：H5 的 JS 调用安卓 / 苹果的方法，比如调用拍照、获取相册、弹窗
2. **原生调用 JS**：安卓 /iOS 代码，调用 H5 页面里的 JS 函数

### 简单理解

- WebView 加载 H5，H5 运行在 WebView 内核里
- H5 本身能力有限，不能直接调用手机摄像头、本地文件；通过 JSBridge 交给原生处理。

## 和 Headless、普通浏览器对比
表格
| 组件 | 界面 | 运行环境 | 用途 |
| --- | --- | --- | --- |
| 普通浏览器 | 有 GUI 窗口 | PC / 手机独立程序 | 用户浏览网页 |
| Headless 无头浏览器 | 无界面 | PC 服务器后台 | 爬虫、自动化测试、截图 PDF |
| WebView | 嵌入 APP 内部，无独立窗口 | Android/iOS App 内部 | 混合开发，App 加载 H5 |

## 总结记忆
- 作用：嵌入到原生APP（安卓/IOS）里面，在APP内部展示H5网页。
- 例子：微信公众号页面、小程序内核、APP里面点开的网页，底层都是WebView。
- 特点：可以实现原生APP代码 和 H5 JS代码互相调用通信。
