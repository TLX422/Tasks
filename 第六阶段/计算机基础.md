## 一、TCP/IP 初识
>[菜鸟教程TCP协议](https://www.runoob.com/np/tcp-protocol.html)
### 1. 全称

**TCP：传输控制协议**
属于**传输层**协议。

### 2. 最简单理解

TCP = **可靠、稳定、有连接**的通信方式
类比：**打电话**

1. 先要接通（建立连接）
2. 说话顺序不乱
3. 对方听不到会重传
4. 确认对方收到信息
5. 通话结束正常挂断

### 3. TCP 三大核心特点

✅ **面向连接**
通信前必须先建立连接（三次握手），通信结束断开连接（四次挥手）。

✅ **可靠传输**
不会丢包、不会乱序。
机制：确认应答、超时重传、流量控制、拥塞控制。

✅ **面向字节流**
把数据当成一串连续字节，没有清晰数据包边界。

### 4. 关键过程

#### （1）三次握手（建立连接）
![](https://www.runoob.com/wp-content/uploads/2025/02/tcp-1.png)
1. 客户端：我想和你通信（SYN）
2. 服务端：收到请求，我准备好了（SYN+ACK）
3. 客户端：收到你的回复，正式开始传输（ACK）

目的：确认双方收发功能正常。

#### （2）四次挥手（断开连接）
![](https://www.runoob.com/wp-content/uploads/2025/02/tcp-2.png)
1. 客户端：我不再发数据（FIN）
2. 服务端：知晓，继续传剩下数据（ACK）
3. 服务端：我数据发完了（FIN）
4. 客户端：收到，可以关闭（ACK）
TCP 是**面向连接**的传输层协议，通信双方传输数据前必须先建立连接，传输结束后释放连接。
1. **可靠传输**：通过确认应答、重传机制，保证数据完整、有序到达，不会丢包乱序。
2. **面向字节流**：把应用层数据看成一串字节流，不保留报文边界。
3. **拥塞控制**：根据网络状况调整发送速度，避免网络过载。
4. **全双工通信**：连接建立后，双方可以同时收发数据。

> 对比：UDP 无连接、不可靠、面向报文，不需要建立连接。

### 2. TCP 报文结构
TCP 报文分为**TCP头部 + 数据部分**，核心头部字段：
- 源端口、目的端口：标识通信两端应用程序
- 序号(seq)：字节流编号，用于排序、重传
- 确认号(ack)：期望收到下一个字节的序号，实现应答
- 标志位：`SYN`建立连接、`FIN`断开连接、`ACK`确认、`RST`重置、`PSH`推送、`URG`紧急
- 窗口大小：流量控制，告诉对方自己最多能接收多少字节
- 校验和：校验报文是否损坏

### 3. TCP 建立连接与释放连接
#### 📌 三次握手（建立连接）
1. 客户端发送 `SYN` 报文，请求建立连接
2. 服务端返回 `SYN+ACK` 报文，同意连接，同时确认客户端请求
3. 客户端发送 `ACK` 报文，确认服务端；连接正式建立，可以传输数据

> 核心目的：协商双方初始序列号，确认收发能力都正常。

#### 📌 四次挥手（释放连接）
TCP是全双工，**两边要分别关闭读写通道**，因此需要四次：
1. 客户端发送 `FIN`，表示客户端不再发送数据
2. 服务端回复 `ACK`，确认收到关闭请求；此时服务端还可以继续给客户端发数据
3. 服务端数据全部发送完毕，发送 `FIN`，服务端也不再发送数据
4. 客户端回复 `ACK`，确认关闭；连接彻底释放

## 二、HTTP 初识
HTTP 是**应用层协议**，基于TCP传输，用于浏览器和服务器之间通信。

### 1. HTTP 报文结构
>[菜鸟教程HTTP协议](https://www.runoob.com/np/http-protocol.html)
分为**请求报文**、**响应报文**

✅ **HTTP请求报文（浏览器→服务器）**
![](https://www.runoob.com/wp-content/uploads/2025/02/http-1.png)
1. 请求行：`请求方法 路径 HTTP版本`，例：`GET /index.html HTTP/1.1`
2. 请求头（Headers）：键值对，携带浏览器信息、Cookie、内容类型等
3. 空行：分隔头部和正文
4. 请求体（Body）：POST/PUT等方法携带提交的数据，GET一般没有请求体

✅ **HTTP响应报文（服务器→浏览器）**
1. 状态行：`HTTP版本 状态码 描述`，例：`HTTP/1.1 200 OK`
2. 响应头（Headers）：键值对，返回服务器信息、数据类型、缓存规则
3. 空行
4. 响应体：真正返回给浏览器的内容（HTML、JSON、图片数据等）

### 2. 状态码含义
状态码为3位数字，第一位代表大类：
|分类|范围|含义|
|---|---|---|
|1xx|100‑199|信息类，临时响应，继续处理请求|
|2xx|200‑299|成功，请求正常处理|
|3xx|300‑399|重定向，需要跳转其他资源|
|4xx|400‑499|客户端错误，请求有问题|
|5xx|500‑599|服务端错误，服务器处理失败|

> 高频记忆：
> - `200 OK`：请求成功
> - `302 Found`：临时重定向
> - `400 Bad Request`：请求参数错误
> - `404 Not Found`：资源找不到
> - `500 Internal Server Error`：服务器内部出错

### 3. 完整的HTTP请求/响应流程
1. 浏览器解析域名，通过DNS获取服务器IP地址
2. 浏览器与服务器完成 **TCP三次握手**，建立TCP连接
3. 浏览器组装HTTP**请求报文**，通过TCP连接发送给服务器
4. 服务器接收解析请求，执行业务逻辑，组装HTTP**响应报文**返回浏览器
5. 浏览器收到响应，解析响应体，渲染页面/处理数据
6. 通信结束，执行TCP**四次挥手**，断开TCP连接

> 补充：HTTP/1.1支持长连接，可以复用TCP连接，不用每次请求都握手挥手。
