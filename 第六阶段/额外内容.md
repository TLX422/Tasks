# 1. ⼀次打开⽹⻚的过程中，哪些环节是“⽹络层”的问题，哪些是“浏览器渲染层”的问题
**网络层**：负责把资源从服务器传输到浏览器本地。
环节：DNS解析、TCP三次握手、TLS加密握手、HTTP请求/响应、资源下载、缓存协商、TCP四次挥手。
典型问题：DNS慢、TTFB高、请求超时、404/502、资源体积过大、跨域报错。

**浏览器渲染层**：拿到资源字节后，浏览器内部解析、计算、绘制出画面。
环节：解析HTML生成DOM树、解析CSS生成CSSOM树、执行JS、构建渲染树、回流（Layout重排）、重绘（Repaint）、图层合成（Composite），最终输出到屏幕。
典型问题：JS长任务阻塞主线程、频繁回流重绘、CSS阻塞首屏渲染、图片解码卡顿。

> 边界记忆：**下载属于网络；解析、计算、绘制、执行JS属于渲染层**。

# 2. DNS解决什么问题？没有DNS用户体验会怎样
- **DNS作用**：域名系统，把人类好记的域名（`www.baidu.com`）翻译成计算机网络识别的**IP地址**。
计算机网络通信只能依靠IP定位服务器，人很难记忆一长串数字IP，DNS充当“地址簿”。

- 如果没有DNS：
1. 用户不能输入域名访问网站，必须手动输入枯燥的IP地址；
2. IP变化时，所有用户都要手动更新IP；
3. 无法做负载均衡、CDN调度，不能把用户调度到就近服务器；
4. 记忆、使用门槛极高，普通互联网几乎无法普及。

# 3. 事件委托（事件代理）：为什么减少监听，代价是什么
### 原理
DOM事件具备**事件冒泡**机制：子元素触发事件，会一层层向上冒泡到父元素。
不在每一个子DOM上绑定`addEventListener`，**只在共同的父容器绑定一次事件**；触发时通过`event.target`判断真正点击的子元素，执行对应逻辑。

✅好处：
1. 大幅减少事件监听器数量，节省内存；
2. **动态新增的子元素不需要重新绑定事件**，新增DOM自动拥有交互。

⚠️代价：
1. 事件需要冒泡传递，有微小性能损耗；嵌套极深的DOM树冒泡链路很长会有开销；
2. 部分事件不冒泡（`blur`、`focus`等），不能直接委托；
3. 需要手动判断`target`，写更多判断逻辑；
4. 如果中间子元素调用 `event.stopPropagation()` 阻止冒泡，委托直接失效；
5. 所有交互全部汇聚到父元素，复杂业务下父回调会变得臃肿。

# 4. 事件循环 和 异步 的关系
> JS是**单线程**，同一时间只能做一件事。
1. **异步是一种代码模式**：遇到定时器、网络请求、用户事件，不会阻塞后面代码，先登记任务，继续跑同步代码。这些任务不会立刻执行。
2. **事件循环是浏览器底层运行机制**，是**实现异步的底层载体**。

关系总结：
- 异步是现象；事件循环是实现这个现象的底层规则。
- 同步代码优先在调用栈执行；异步任务（宏任务、微任务）先放入队列；
- **事件循环不停循环：调用栈清空 → 优先清空全部微任务 → 取一个宏任务执行，循环往复**。

示例：
```js
console.log(1);
setTimeout(()=>console.log(2),0);
Promise.resolve().then(()=>console.log(3));
console.log(4);
//输出：1 4 3 2
```

# 5. 页面卡顿的一个典型原因
> **主线程被长任务阻塞（Long Task）**
一段同步JS计算量巨大（比如循环处理几万条数据、复杂大循环），长时间霸占JS主线程。
> 
浏览器主线程既要执行JS，又要处理DOM事件、渲染页面；主线程被占住时，用户点击、滚动、页面渲染得不到执行，页面出现点击无响应、滚动卡顿、掉帧。

其他常见卡顿原因：频繁触发回流重绘、大量DOM操作没有做DocumentFragment缓冲、图片过多解码占用主线程。
